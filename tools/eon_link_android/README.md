# 이온링크 0.1.0

이온 ↔ Snapdragon 스마트폰의 N16 **성능 시험용** 앱이다. 인터넷은 기존 중간
핫스팟을 유지한다. 이 앱이나 이온 클라이언트는 차량 제어 결과를 발행하지 않는다.

## 설치·실행

1. `g_blinker`를 업데이트하고 이온을 재시작한다.
2. Releases의 `eon-link-android`에서 `EON-Link.apk`를 설치한다.
   패키지는 `ai.comma.eonlink`이며 기존 젯링크를 덮어쓰지 않는다.
3. 기존 젯링크를 종료한다. 두 앱의 원본 엔진이 같은 5599 포트를 사용한다.
4. 이온과 폰을 기존 핫스팟에 연결하고 **이온링크 → 연결 시작**을 누른다.
5. **N16 다운로드** 후 완료되면 **N16 준비 / 사용**을 누른다.
   별도 앱 저장 공간이라 최초 한 번 모델을 다시 받는다. 직접 가진 동일 N16
   `.onnx`를 가져올 수도 있다. 준비·컴파일 중에는 시간이 걸릴 수 있다.
6. 이온웹 → 도구 → 이온링크/젯링크 시험에서 앱을 **이온링크**, 포트를
   **5600**, IP는 빈칸(자동 검색) 또는 앱에 표시되는 Wi-Fi IP로 둔다.
7. **무손실 압축은 우선 끄고**, P단 정차·인게이지 해제 상태에서
   **N16 처리·전송 속도 / 1분**을 실행한다.
8. 새 결과 화면 또는 `최근 결과 저장` JSON으로 기존 수치와 비교한다.
   원시 통신 지연부터 확인한 뒤 같은 조건의 압축 켜기 시험을 비교한다.

IP·포트·앱 종류·압축 선택은 같은 웹 브라우저에 저장된다. IP가 바뀌면 자동 검색을
사용하거나 새 주소로 수정한다. 핫스팟의 브로드캐스트 차단으로 자동 검색이 안 되면
수동 IP를 사용한다. 여러 폰이 발견되면 임의 선택하지 않고 주소를 요청한다.

알림이 있는 동안 foreground service와 CPU/Wi-Fi lock을 유지한다. 화면을 꺼도
서비스는 유지되지만 제조사 절전 정책·전파 상태를 우회한다고 보장하지 않는다.
중지 버튼/알림으로 종료한다. 부팅·연결 끊김 후 임의로 재시작하지 않는다.

## 변경 내용과 한계

- 한국어 화면, 다운로드/준비/로그만 있는 별도 앱이다. 기존 APK의 화면·DEX를
  수정하지 않고 새 manifest·Java 소스를 빌드한다.
- 기존 v0.9.0-carrot.46 N16 계산 엔진과 Snapdragon ORT/QNN 런타임만 재사용한다.
  준비·해시·모델 규격·출력 검증을 유지하며 숨은 상태를 직접 수정하지 않는다.
- EON1 envelope는 영상과 float를 **무손실**로 전달한다. 선택적 zlib level 1
  압축이 5% 이상 줄일 때만 압축본을 보낸다. 랜덤 합성 영상은 잘 압축되지 않는다.
  압축 비용이 이온에서 더 클 수도 있으므로 기본은 꺼짐이다.
- 한 EON만 연결하고 추론 요청은 한 개씩 처리한다. 이온은 응답을 받은 뒤 최신
  카메라 프레임을 읽으므로 밀린 프레임을 대기열에 쌓지 않는다. 이미 오래된 결과를
  실제 제어에 재활용하는 기능은 없다. 느린 프레임도 시험 수치에는 그대로 남긴다.
- **자동 검색은 있다. 자동 재연결은 아직 없다.** 시험 중 연결이 끊기면 종료하고
  오류를 보존한다. 다음 시험에서 다시 검색·연결한다.
- 네이티브 엔진에 직접 새 추론 API를 추가한 것은 아니다. 앱의 전용 relay가
  localhost TCP로 기존 엔진과 통신한다. 이 추가 단계의 비용도 측정한다.
- native engine의 진단 포트 5599도 열린다. EON1/검색은 인증·암호화 프로토콜이
  아니다. 기존 로컬 진단 포트와 같은 신뢰된 시험 네트워크용이며 외부 공개 금지다.
- Android 12+, arm64, Snapdragon NPU(기존 `htp-whole` 경로) 대상으로 만들었다.
  다른 칩용 LiteRT/GPU 런타임은 이 앱에 넣지 않았다.
- 지도 렌더러, EON 영상의 N16 호환성, 주행 메시지 변환, 실제 주행 복귀 제어는
  기존 시험 단계의 남은 작업 그대로다. 이 앱으로 해결했다고 판정하지 않는다.

## 시간 구간

모델 준비 전에 작은 요청 32바이트와 영상 크기 요청 393216바이트를 각각 5번
전송한다. 폰은 수신한 원문의 SHA-256 32바이트만 반환한다. 이 구간은 엔진에
연결하지 않아 모델·회귀 상태에 영향을 주지 않는다. 순수 무선 지연만이 아니라
양단의 처리·소켓 지연도 포함하는 **모델 없는 왕복 기준값**이다.

각 N16 응답에는 폰이 측정한 다음 시간을 붙인다. 서로 다른 기기의 시계를 빼지
않고 각 기기 내부의 monotonic clock 간격만 사용한다.

| 구간 | 정의 |
|---|---|
| 폰 수신 | 요청 첫 바이트부터 전체 요청 수신까지. 전송 전에 양단에서 기다린 시간은 제외된다 |
| 폰 압축 해제 | 요청 해석·해제 시간 |
| 폰 내부 엔진 왕복 | 폰이 엔진에 요청을 전달하기 직전부터 전체 결과 수신까지. 모델 시간 외 loopback·엔진 큐·결과 직렬화도 포함한다 |
| 이온 압축 | 이온 송신 구간에 포함된 압축 시도 비용. 다른 구간에 다시 더하지 않는다 |
| 왕복 | 이온 요청 구성 시작부터 출력 검증 완료까지. 엔진 보고 시간·폰 구간이 그 안에 포함된다 |

추가 relay·압축·Wi-Fi lock이 기존 118ms를 해결한다고 보장하지 않는다.
실제 NPU·열·핫스팟 성능은 S23에서 재측정해야 한다.

## 빌드와 검증

`build.py`는 upstream APK를 고정 URL·SHA-256으로 확인하고 필요한 네이티브
라이브러리만 가져온다. 별도 실행 파일로 QNN을 배포하지 않는다. 출처·라이선스는
`NOTICE.txt` 및 `JETLINK-LICENSE`에 기록하며 APK assets에도 포함한다.

```sh
# JDK 17, Android SDK platforms;android-35 / build-tools;35.0.0 필요
export EONLINK_STORE_PASSWORD=...
export EONLINK_KEY_PASSWORD=...
python tools/eon_link_android/build.py --keystore /path/to/key.p12 --alias your-alias
python -m pytest -q selfdrive/modeld/jetlink/tests
```

GitHub Actions는 기존 `REMOTE_HUD_*` 서명 secrets를 사용하고 기존 서명 지문을
검증한다. 임시 로컬 시험 서명의 APK는 배포본과 섞지 않는다. 릴리스 앱은 같은
기존 키로 계속 서명한다. CI 빌드 번호는 Android versionCode로 증가한다.

Python/Java TCP 통합 시험은 APK에 들어가는 실제 `Wire`/`Relay` 소스와 가짜
추론 엔진으로 규격·원문 보존·지도 변경·크기 제한·압축 오류·측정 수치를 확인한다.
가짜 엔진 수치를 실제 NPU 성능으로 보고하지 않는다. APK 컴파일·서명 검증과
실기기 실행 검증은 별개다.

## 주행 제어 연동 진행 상태

현재 `prediction.py`는 N16의 경로·속도·가속도·회전율·차선·도로 경계·세 개 앞차·
메타·자기운동 출력을 구형 EON `ModelDataV2`/`CameraOdometry` 필드로 변환한다.
N16의 한 경로를 구형 모델의 다섯 후보 배열로 캐스팅하지 않고, 앞차 세 출력을
각각 보존한다. 메타의 6개 간격과 구형 모델의 7개 간격도 구분한다.

이 변환 결과는 **제어 토픽으로 발행하지 않는다.** `control_adapter.applied`와
`camera_compatible`는 여전히 false다. 실제 카메라 시험을 완료하면 마지막 실제
영상의 변환 결과를 `/data/eon-n16-benchmark.candidate.json`에 저장하고, 이온웹의
**변환 출력 저장**에서 받을 수 있다. 현재 시험과 다른 오래된 후보는 내려주지 않는다.
합성 시험은 실제 카메라 후보를 만들지 않는다.

다음에 필요한 자료는 새 이온링크의 **EON 실제 카메라 / 1분** 결과 JSON과 변환
출력 JSON이다. 정차·인게이지 해제 조건은 유지한다. 카메라 입력의 시야·좌표,
전처리·추론을 포함한 지연, 기존 이온 모델과 경로·속도·앞차 차이를 확인해야 한다.
이 자료 없이 기존 `modelV2`를 대체하거나 순간 복귀를 켜면 검증하지 않은 경로가
조향·가감속에 들어갈 수 있다. 출력 형식이 맞는 것만으로 제어 적합성을 판정하지 않는다.

따라서 출력 변환은 구현됐지만 **실제 주행 제어 선택·복귀·활성화는 아직 구현하지
않았다.** 속도 결과가 통과하면 자동으로 제어가 활성화되는 기능도 없다.
