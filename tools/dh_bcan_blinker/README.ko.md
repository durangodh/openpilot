# 제네시스 DH 자동 깜빡이 (ESP32 + B-CAN)

리모컨·NOO로 오픈파일럿이 차로를 바꿀 때, EON이 Wi-Fi로 ESP32에 요청하면 ESP32가 B-CAN에
**순정 원터치 레버 신호(0x138)** 를 한 번 보냅니다. BCM이 순정 원터치처럼 **외부 램프를 5번** 깜빡입니다.
(2026-11-14 실차 확인: 원터치 1회 = 외부 램프 5회, 경고 없음)

- ESP32 펌웨어: `tools/dh_bcan_blinker/dh_bcan_blinker.ino`
- EON 쪽: `selfdrive/eon_cluster/bcan_blinker.py` (설정 **DH B-CAN BLINKER (ESP32)**)
- 배선도: `tools/dh_bcan_tx_test/final_wiring.png`

## 1. 배선
| 연결 | |
|---|---|
| M01 **1번 녹색** | 보드 CAN **H** |
| M01 **2번 주황** | 보드 CAN **L** |
| 시동 연동 12V (퓨즈 탭, IGN, 2A) | 보드 DC 단자 **VIN** |
| 차체 접지 | 보드 DC 단자 **GND** |

- **보드 CAN 점퍼는 반드시 NC.** (120R이면 B-CAN이 무너져 수신도 안 됩니다)
- 상시 전원(B+)에 연결하지 마세요. 시동을 끄면 보드도 꺼져야 합니다.
- 보드 USB는 **충전기(전원만)** 에 꽂으세요. OTG 허브·헤드유닛 USB처럼 장치를 인식하는 쪽에 꽂으면
  예전 펌웨어(2026-11-15 이전)는 시리얼 출력이 막혀 몇 초씩 멈춥니다(깜빡이가 차로변경 끝에 켜짐).
  2026-11-15 이후 펌웨어는 그래도 멈추지 않지만, 충전기 연결을 권장합니다.

## 2. 휴대폰 핫스팟 (S20)
- 설정 → 연결 → 모바일 핫스팟 및 테더링 → 모바일 핫스팟 → ⋮ → 구성 → **대역 2.4GHz**
  (ESP32는 5GHz에 접속하지 못합니다)
- EON도 같은 핫스팟에 접속해 있어야 합니다(지금처럼).

## 3. 펌웨어 올리기 (처음 한 번)
1. `dh_bcan_blinker.ino`를 새 스케치에 붙여넣습니다. (코드에 비밀번호를 적지 않아도 됩니다)
2. 보드: ESP32S3 Dev Module, USB CDC On Boot: Enabled → 업로드.

## 3-1. 핫스팟 등록 (펌웨어 다시 올릴 필요 없음)
핫스팟은 보드 안에 **최대 4개** 저장되고, 전원이 꺼져도 남습니다. 켜진 것에 자동으로 연결합니다.

**휴대폰으로 (노트북 없이)**
1. 저장된 핫스팟에 **30초** 동안 연결되지 않으면(처음엔 3초) 보드가 설정용 Wi-Fi를 엽니다.
   - 이름 **`DH-Blinker-Setup`**, 비밀번호 **`dhblinker`**
2. 휴대폰 Wi-Fi에서 그 이름에 접속하면 설정 화면이 뜹니다. 안 뜨면 브라우저에서 **http://192.168.4.1**
3. 핫스팟 이름(예: `G80`)과 비밀번호를 넣고 **저장하고 연결**.
4. 휴대폰 핫스팟을 켜 두면 보드가 접속합니다. 설정용 Wi-Fi는 연결된 뒤 2분이 지나면 저절로 닫힙니다.
   - 같은 화면에서 저장된 핫스팟을 **삭제**할 수 있습니다. 새로 저장한 것을 먼저 연결합니다.

**노트북 시리얼 모니터로 (115200, New Line)**
| 입력 | 동작 |
|---|---|
| `w G80\|비밀번호` | 핫스팟 저장하고 바로 연결 (이름과 비밀번호 사이에 `\|`) |
| `wl` | 저장된 목록 |
| `wd 2` | 2번 삭제 |
| `wp` | 설정용 Wi-Fi 바로 열기 |
| `s` | 현재 연결된 핫스팟·신호·B-CAN 상태 |

연결되면 시리얼에 `Wi-Fi connected: "G80" 192.168.x.x, rssi -55 dBm`이 나옵니다.

## 4. EON 설정
- 설정 → **네비MAP** 탭 → **DH B-CAN BLINKER (ESP32)** 켜기 (재부팅 필요 없음, 2초 안에 적용)
- 리모컨 차로변경을 쓰려면 기존처럼 **BLUETOOTH REMOTE**도 켜져 있어야 합니다.

## 5. 화면 표시 (EON 주행 화면 오른쪽 아래, S20 HUD 리모컨 상자 아래)
| 표시 | 의미 |
|---|---|
| 🟢 깜빡이 연결됨 -55dBm | ESP32 Wi-Fi·B-CAN 모두 정상 |
| 🟡 깜빡이 B-CAN 없음 | Wi-Fi는 되지만 0x138이 안 들어옴 (배선, 점퍼 NC, 시동) |
| ⚪ 깜빡이 연결 안 됨 | 6초 넘게 ESP32 신호 없음 (핫스팟 꺼짐/5GHz, 보드 전원, 비밀번호) |
| 🔴 깜빡이 버스 오류 | 최근 1분 안에 송신 오류 → ESP32가 그 요청을 중단함 |
| 깜빡이 좌 켬 (하늘색 테두리) | 원터치 요청 성공 (3초 표시) |
| 깜빡이 좌 · 레버 사용 중 등 (주황 테두리) | 요청이 거부됨, 이유 표시 |

## 6. 동작 규칙
- 오픈파일럿 조향 중 차로변경이 **준비(preLaneChange) 또는 시작**되면 그 방향으로 1회 요청합니다.
- 차로변경이 4.5초 넘게 계속되면 다시 요청합니다(최대 3회, 약 13초).
- **운전자가 레버로 시작한 차로변경**(이미 같은 쪽 램프가 켜져 있음)에는 보내지 않습니다.
- ESP32는 다음 경우 보내지 않습니다: 레버가 중립이 아님, 최근 0.8초 안에 램프가 켜져 있었음
  (레버·비상등·이전 원터치), 순정 0x138이 0.5초 넘게 안 들어옴, 직전 원터치 끝난 뒤 3.5초 이내,
  버스 오류.

## 7. 처음 확인 순서
1. 주차(P), 시동 ON 상태에서 보드에 노트북을 연결하고 시리얼 모니터에서 `l`, (4초 뒤) `r`
   → 외부 램프 5회씩. `s`로 Wi-Fi·B-CAN 상태 확인.
2. EON 주행 화면과 S20 HUD에 **깜빡이 연결됨**이 뜨는지 확인.
3. 안전한 도로에서 리모컨 차로변경 → 외부 램프 5회, 화면에 **깜빡이 좌/우 켬**.
4. 처음 며칠은 다음 날 아침 시동·스마트키·문 잠금·계기판 경고를 확인하세요.
   이상이 있으면 보드 선을 빼면 원래대로 돌아옵니다.

## 8. 차로변경 끝나면 남은 점멸 끄기 (시험 중)
원터치는 5번 깜빡이지만 차로 하나는 보통 2~3번이면 끝납니다. 남은 점멸이 뒤차에게 또 바꾸는 것처럼
보이지 않게, 차가 차선을 넘어가면(주행 모델의 차선 인식, 차선이 없으면 차로변경 시작 2초 뒤) ESP32가 **반대쪽으로 레버를 짧게** 쳐서 끕니다.

1. **먼저 P단에서 확인** (펌웨어 2026-11-15 이후, 노트북 시리얼 모니터):
   `l` 입력 → 깜빡이 시작 → 약 1.5초 뒤 `c` 입력.
   - 왼쪽 깜빡임이 **멈추고 오른쪽은 켜지지 않으면** 성공.
   - 오른쪽 깜빡이가 새로 켜지면 이 기능은 쓰지 마세요(DH에서는 취소가 안 되는 것).
2. 성공했으면 설정 **DH BLINKER STOP AFTER LANE CHANGE** 켜기 (기본 꺼짐).
- ESP32는 자기가 켠 원터치가 아직 깜빡이는 중이고, 그 뒤 운전자가 레버를 건드리지 않았을 때만 보냅니다.
- 기록: `/data/bcan_blinker.log`의 `lane line crossed`, `cancel seq ... sent`, `ESP32 answer cancel ...` 줄.

## 10. 리모컨 = 깜빡이 레버
- 리모컨 차로 좌/우 버튼을 누르면 **속도·기어·브레이크와 관계없이** 바로 그쪽 원터치 깜빡이(5회).
- 차로변경은 레버로 깜빡이를 켰을 때와 같은 조건: D단, 페달 안 밟음, 오픈파일럿 조향 중,
  **AUTO LANE CHANGE MIN SPEED 이상**(레버와 같은 속도). 시작 대기는 REMOTE LANE CHANGE DELAY.
- 차로변경 중이 아닐 때 깜빡이는 동안(약 3.5초) 한 번 더 누르면 깜빡이를 끕니다.
  끈 직후 3.5초 동안은 새 원터치를 받지 않습니다.
- 기록: `/data/bcan_blinker.log`의 `remote: tap ...`, `remote: cancel ...` 줄.

## 11. 리모컨 깜빡이 계속 켜기 (DH BLINKER HOLD, 펌웨어 2026-11-16)
- 설정 **DH BLINKER HOLD (REMOTE)** 켜짐: 리모컨 좌/우를 누르면 **반대쪽 버튼을 누를 때까지** 계속 깜빡입니다.
  같은 쪽 버튼은 아무 변화 없음.
- ESP32가 원터치가 끝나기 전(2.8초마다, 또는 램프가 0.6초 꺼져 있으면) 같은 쪽 원터치를 다시 넣습니다.
- 꺼지는 경우: 반대쪽 버튼, 운전자 레버, 차선을 넘어 차로변경 끝남(STOP AFTER LANE CHANGE 켜짐),
  이온 신호 8초 끊김, 3분 경과, 버스 오류.
- **P단 시험 먼저**: 시리얼 `kl` → 10초 넘게 끊김 없이 깜빡이는지(5번마다 멈칫하는지) → `c`로 끄기.

## 12. B-CAN 스캔 (버튼이 B-CAN 메시지를 내는지 찾기, 수신만)
- 폰: `http://보드IP/scan?start=1` → 4초 동안 아무것도 만지지 않기(학습) → 40초 동안 찾을 버튼
  (예: 비상등)을 몇 초 간격으로 눌렀다 떼기 → 페이지가 2초마다 새로 고쳐지며 바뀐 메시지가 쌓입니다.
  빨간 글씨가 바뀐 바이트입니다. 시리얼에서는 `scan`.
- 차에는 아무것도 보내지 않습니다.

## 13. 저속 CAN 칩(TJA1055) 모듈 사용 (권장 업그레이드)
보드 자체 CAN 칩은 고속용이라 저속 B-CAN에 직결하면 송신 중 가끔 버스 오류가 납니다(HOLD에서 30초에 한 번꼴).
TJA1055T/3 모듈은 B-CAN과 같은 저속 내결함 규격이라 이 오류가 없어집니다.

**준비물**: TJA1055**T/3** 모듈(끝의 /3 = 3.3V 로직), 듀폰선.

**배선 (시동·전원 끄고)**
| 연결 | |
|---|---|
| 보드 헤더 **5V** | 모듈 **VCC** |
| 보드 헤더 **GND** | 모듈 **GND**, 그리고 **차체 접지**(M01 6번 또는 차체 볼트) |
| 보드 **IO4** | 모듈 **TXD** |
| 보드 **IO5** | 모듈 **RXD** |
| 보드 **IO6** | 모듈 **EN** |
| 보드 **IO7** | 모듈 **STB**(STB_N) |
| 모듈 **BAT** (있으면) | 보드와 같은 **IGN 12V** |
| 모듈 **CANH** | M01 **1번 녹색** |
| 모듈 **CANL** | M01 **2번 주황** |
- **보드 자체 CAN 단자(초록 단자대)의 B-CAN 선은 뺍니다.** 두 칩을 동시에 B-CAN에 물리지 마세요.
- 모듈의 RTH/RTL 종단은 모듈 기본값 그대로. 120Ω을 추가하지 마세요.
- 모듈의 WAKE/INH/ERR 핀은 모듈 설명서대로(보통 비워 둠).
- 이 방식은 절연이 아니므로 GND를 꼭 차체와 같이 연결합니다.

**펌웨어**
1. 배선 후 시동 ON: 지금 펌웨어는 보드 단자를 보므로 화면에 "깜빡이 B-CAN 없음"이 뜨는 게 정상입니다(Wi-Fi는 됨).
2. 폰으로 `bin/dh_bcan_blinker_tja1055.ino.bin`을 받아 `http://보드IP/update`로 올립니다.
3. 현재 버전이 **2026-11-16g-tja1055**이고 화면이 "깜빡이 연결됨"이면 완료.
4. P단에서 리모컨으로 원터치·HOLD 시험. 되돌리려면 일반 bin을 올리고 보드 단자 배선으로 복구.

### 13-1. 저속↔고속 변환기(M-CAN용 TJA1054 박스)로 시험 (TJA1055 모듈 대신)
처음 변환기 시험은 보드 점퍼 120R로 해서 실패했고, 변환기 + 점퍼 **NC** 조합은 아직 시험하지 않았습니다.
1. 변환기 저속 쪽 CANH/CANL → M01 1번/2번, 고속 쪽 CANH/CANL → 보드 CAN 단자, 전원·접지는 변환기 설명대로.
2. **보드 점퍼 NC.** 변환기 고속 쪽 종단은 기본값.
3. 시동 ON·P단에서 **순정 레버 깜빡이가 정상인지 먼저** 확인(안 되면 즉시 분리).
4. 정상이면 일반 펌웨어(`dh_bcan_blinker.ino.bin`) 그대로 리모컨 원터치·HOLD 시험, 기록에 `link 3`이 생기는지 확인.
