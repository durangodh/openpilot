# 제네시스 DH M-CAN 게이트웨이 (ESP32-C6)

여분 블랙판다가 하던 M-CAN 게이트웨이를 ESP32-C6 보드로 바꾼다. 규칙은 판다 게이트웨이
(`panda/board/safety/safety_mcan_gateway.h`)와 같다.

- 양쪽 신호를 전부 통과시킨다.
- 메인 판다가 보내는 우리 HUD 안내(0x115, 0x123, 0x1E5, 0x4A9)가 나가는 동안(0.3초 이내)에는
  순정 내비(AVN)의 같은 신호를 HUD 쪽으로 넘기지 않는다. 우리 안내가 멈추면 다시 통과시킨다.
- 우리 안내는 차량 쪽으로 넘기지 않는다.

**아직 실차 확인 전이다(2026-11-26: 빌드만 확인).** 처음에는 아래 "첫 시험" 순서대로 한다.

## 1. 부품
| 부품 | 수량 | 비고 |
|---|---|---|
| ESP32-C6 개발 보드 | 1 | CAN 2채널 칩. ESP32-S3 는 1채널이라 안 된다 |
| 3.3V 고속 CAN 트랜시버 모듈 (SN65HVD230) | 2 | TJA1055(저속) 아님 |
| 5V 전원 | 1 | 12V→5V 변환 모듈, 또는 시동 연동 차량용 USB 충전기 + USB-C 케이블 |

CANBridge-LS 변환기, 토글 스위치, 풋램프 12V 배선은 지금 그대로 쓴다.

## 2. 배선 (판다 자리만 교체)
| 지금 판다 연결 | 바뀐 뒤 |
|---|---|
| 26핀 4·6번 (CANBridge-LS 고속 쪽 H·L, 차량 쪽) | CAN 모듈 A 의 CANH·CANL |
| 8핀 8·7번 (스위치에서 오는 HUD 쪽 H·L) | CAN 모듈 B 의 CANH·CANL |
| 8핀 1번 12V | 12V→5V 모듈 입력 → 보드 5V |
| 8핀 4번 접지 | 보드 GND, 모듈 A·B 의 GND |

| ESP32-C6 | 모듈 A | 모듈 B |
|---|---|---|
| 3V3 | 3V3(VCC) | 3V3(VCC) |
| GND | GND | GND |
| GPIO2 | TX(CTX, D) | |
| GPIO3 | RX(CRX, R) | |
| GPIO6 | | TX(CTX, D) |
| GPIO7 | | RX(CRX, R) |

- H·L 쌍만 맞으면 된다. 어느 모듈이 차량 쪽이고 HUD 쪽인지는 보드가 신호를 보고 스스로 찾는다.
- 모듈의 종단 저항(120Ω): 모듈 A(차량 쪽, CANBridge-LS 와 연결)는 그대로 둔다. 모듈 B(HUD 쪽)는
  먼저 그대로 두고 시험하고, HUD 쪽 버스오류가 계속 늘면 저항을 떼고 다시 시험한다(실차 확인 필요).
- 보드 전원이 꺼지거나 다시 시작하는 동안에는 HUD 쪽이 차와 끊긴다. 토글 스위치의 "차량" 쪽이 직결이다.

## 3. 펌웨어 올리기
- 처음: 아두이노 IDE(Arduino-ESP32 3.x), 보드 "ESP32C6 Dev Module", USB CDC On Boot: Enabled 로
  `dh_mcan_gateway.ino` 를 업로드한다.
- 그다음부터: 폰으로 `http://보드IP/update` (아이디 `dh`, 비밀번호 `dhmcangw`)에
  `bin/dh_mcan_gateway.ino.bin` 을 올린다. 현재 파일: 버전 2026-11-26a, sha256 앞자리 `1ee04cc2c3f7c352`.

## 4. Wi-Fi
- 저장된 핫스팟이 없으면 3초 뒤(있는데 30초 동안 못 붙으면) 설정용 Wi-Fi `DH-MCAN-GW`
  (비밀번호 `dhmcangw`)를 연다. 폰으로 접속해 `http://192.168.4.1/wifi` 에서 핫스팟을 저장한다.
- 시리얼(115200)로 `w 이름|비밀번호` 를 보내도 된다. `s` 는 상태.
- 게이트웨이 동작은 Wi-Fi 와 상관없이 전원이 들어오면 바로 시작한다.

## 5. 첫 시험 (P단, 시동 ON)
1. 토글 스위치를 "차량"(직결)에 두고 보드 전원만 넣는다. `http://보드IP/` 에서 모듈 A·B 의
   "받음" 숫자가 0 인지(직결 중이라 보드로는 안 온다), 보드가 켜졌는지만 본다.
2. 스위치를 "판다(게이트웨이)" 쪽으로 돌린다. 순정 HUD 가 평소처럼 나오고, 상태 화면에서
   - "차량 쪽 / HUD 쪽"이 "확인됨"으로 바뀌고,
   - 두 모듈의 "받음"·"넘김"이 계속 늘고, "못 보냄"·"버스오류"가 늘지 않으면 정상이다.
3. 순정 내비로 목적지를 찍어 순정 안내가 HUD 에 나오는지 본다(우리 안내가 없을 때 통과).
4. 오픈파일럿 안내(티맵·네이버)를 켜서 HUD 가 깜박이지 않는지, "막은 순정 안내"가 느는지 본다.
5. 이상하면 스위치를 "차량" 쪽으로 돌리면 바로 원래대로다. `http://보드IP/log` 화면을 남긴다.
