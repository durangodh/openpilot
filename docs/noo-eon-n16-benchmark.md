# EON ↔ S20 N16 연결·속도 시험

`g_blinker`에서 외부 N16의 실제 처리 시간을 확인하기 위한 첫 단계다.
**주행 모델 교체 기능은 아니다.** EON의 기존 모델은 계속 실행되고,
외부 결과를 `modelV2`, `cameraOdometry`, 조향·가감속 명령으로 발행하지 않는다.

## 실행

1. `g_blinker`를 업데이트하고 재부팅한다. 카메라 시험에는 변경된 `modeld`의
   네이티브 빌드가 필요하다. 일반 업데이트 빌드에서 함께 처리한다.
2. S20에서 N16을 지원하는 Jetlink Carrot 앱을 실행한다.
   [공식 carrot.46 APK](https://github.com/bin9208/jetlink/releases/download/v0.9.0-carrot.46/jetlink-carrot-0.9.0-carrot.46.apk).
   N16을 선택하고 다운로드·준비를 완료한다. 이온웹은 모델을 임의로 바꾸거나 업로드하지 않는다.
3. 앱의 설정 → About에서 Version을 7번 눌러 Developer를 표시한다.
   개발자 TCP 포트가 열리며 Wi-Fi 주소·포트를 확인할 수 있다. 기본 포트는 5599다.
4. EON과 S20을 같은 핫스팟에 연결한다. 이번 시험은 Wi-Fi/TCP 방식이며
   EON USB·판다·핫스팟 설정을 자동 변경하지 않는다.
5. 시동을 켜고 **P단, 완전 정차, openpilot 인게이지 해제** 상태로 둔다.
6. 이온웹 → **도구 → S20 N16 연결·속도 시험**에서 S20 주소를 입력한다.
   처음에는 **N16 처리·전송 속도 / 1분**으로 시작한다.
7. 응답이 정상적으로 오면 **EON 실제 카메라 / 1분**, 이어서 **10분**으로
   발열 후 지연을 비교한다. 화면의 중지 버튼으로 종료할 수 있다.
8. **최근 결과 저장**으로 `eon-n16-benchmark.json`을 받는다.

차량 CAN 상태·P단·정차·인게이지 해제 조건을 시험 프로세스에서 계속 확인한다.
실제 영상의 추가 GPU 읽기는 네이티브 modeld에서도 별도로 같은 조건을 확인한다.
시험이 종료되거나 프로세스가 사라지면 영상 요청은 2초 안에 만료된다.

## 무엇을 측정하는가

| 입력 | 내용 | 알 수 없는 것 |
|---|---|---|
| N16 처리·전송 속도 | N16과 같은 크기의 고정 영상, 59개 float, 지도 입력을 20Hz 목표로 전송 | 카메라 전처리 비용·영상 호환성·주행 품질 |
| EON 실제 카메라 | 내부 모델이 준비한 최신 두 시야의 8비트 영상과 desire·통행 방향, 현재 내비의 47개 안내 입력 | EON 단일 카메라/기존 warp가 N16 학습 입력과 일치하는지 여부 |

EON은 카메라 하나를 서로 다른 변환으로 두 시야에 사용한다. 실제 두 카메라를
사용한 N16의 입력과 동등하다고 검증하지 않았다. 기존 모델의 GPU 입력은
읽기만 하며 추론 버퍼·회귀 상태를 변경하지 않는다. 진단용 파일이 잠겼으면
기다리지 않고 해당 영상의 추가 출력을 건너뛴다.

`action_t` 두 값은 이 성능 시험에서 고정 0.2초다. 실제 제어 지연 보정값으로
검증한 값이 아니며, 결과는 차량 제어에 사용할 수 없다.

첫 20회는 워밍업으로 제외한다. 이후 왕복 평균·p99·최대, 서버 처리 시간,
입력 준비 시작부터 응답까지의 p99·최대, 50ms 초과 횟수, 건너뛴 영상을 기록한다.
**50ms 이내여도 주행 승인 판정은 하지 않는다.** Wi-Fi 결과는 USB 연결 성능의 증명이 아니다.

기록 위치:

- 현재 상태: `/dev/shm/eon-n16-status.json`
- 최근 완료/중지/오류 결과: `/data/eon-n16-benchmark.json`
- 실행 오류 로그: `/dev/shm/eon-n16-worker.log`

## 지도 입력과 남은 작업

원본 `mapsd` 형식의 `/dev/shm/carrot-nav-map`이 있고 0.5초 미만으로 신선하면
그 지도를 사용한다. 없거나 오래됐으면 원본의 무경로 입력인 검은 지도를 보낸다.
**이 EON 브랜치에는 아직 N16용 지도 타일 렌더러가 없다.** 웹의 경로 미리보기를
학습용 지도로 대체하지 않는다. 화면과 결과 파일에 `nav_map: blank`가 표시된다.

따라서 이번 코드는 N16 연결·전송·추론 응답을 확인하는 시험 단계다.
지도 기반 NOO 주행을 완성하려면 지도 렌더러, EON 카메라 변환의 모델 적합성,
N16 출력에서 구형 EON 모델 메시지로의 변환, 실제 지연·복귀 동작을 별도로 구현·확인해야 한다.

## CLI

EON에서 같은 시험:

```sh
cd /data/openpilot
python3 -m selfdrive.modeld.jetlink.benchmark --host 192.168.0.9 --seconds 60 --source synthetic
python3 -m selfdrive.modeld.jetlink.benchmark --host 192.168.0.9 --seconds 60 --source camera
```

주소는 S20에 표시된 값으로 바꾼다. `--standalone`은 차량 메시지가 없는 Linux PC의
통신 시험 전용이며, 합성 입력만 허용한다. 이온웹에서는 이 옵션을 사용하지 않는다.

## 코드 기준과 검증 범위

- Jetlink v3 ABI: `bin9208/jetlink` `carrot-noo` `1133658a61df201ef8b1805fa3e03e493604355b`,
  `JetlinkKit/Sources/JetlinkServer/WireProtocol.swift` 및 `Session.swift`.
- N16 규격: `ajouatom/openpilot` `c18326a46`, `rust/crates/jetlink/data/n16.json`.
- 호스트 시험은 가짜 TCP 상대와의 핸드셰이크·전체 크기 전송, 출력 검증,
  중단 조건, C++→Python 공유 영상 레이아웃을 확인한다. 가짜 상대의 숫자를
  실제 N16 또는 S20 성능으로 보고하지 않는다.
- EON 전체 네이티브 빌드, 실제 S20 추론 시간·온도, 카메라 변환은 아직 기기에서 확인하지 않았다.
